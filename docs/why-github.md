# Why GitHub?

This repository is not only a code archive. It is a public research
notebook.

GitHub allows Earth Sensors Lab to document:

- evolving research questions
- curriculum modules
- prototype decisions
- accessibility requirements
- pilot templates
- sensor schemas
- software concepts
- partnership language
- open-source implementation paths

The repository helps collaborators understand not only what we are
building, but why we are building it.

## What this means in practice

- **Commit history as research history.** Because research questions,
  curriculum, and prototype status all live in version-controlled Markdown,
  the history of how a question moved from `OPEN QUESTION` toward `EMERGING`
  (see [research-questions.md](../research/research-questions.md)) is
  itself part of the record — not erased each time a page is rewritten.
- **Issues as the intake channel.** Questions, pilot proposals, and
  accessibility feedback come in through GitHub Issues (see
  [CONTRIBUTING.md](../CONTRIBUTING.md)) rather than a private inbox, so the
  conversation that shapes the lab's direction is itself visible.
- **No separate "internal" version.** What a funder, a university
  collaborator, a teacher, and a contributor each see is the same
  repository — there is no polished public-facing summary that diverges
  from the working documentation. [/docs/grant-language.md](grant-language.md)
  and [/docs/one-page-summary.md](one-page-summary.md) are reader-friendly
  entry points into the same source, not a separate narrative.
- **Schema cards and JSON Schemas as machine-readable research design.**
  [SCHEMA_CARD.md](../SCHEMA_CARD.md) and [/schemas/](../schemas/) make the
  repository legible to tooling, not only to human readers — a step toward
  the eventual open-source toolkit in [ROADMAP.md](../ROADMAP.md) Phase 5.

## What this is not

Not a claim that GitHub substitutes for a lab notebook's rigor, an IRB's
oversight, or a funder's due diligence — see
[/research/study-protocols.md](../research/study-protocols.md) and
[ETHICS_AND_CONSENT.md](../ETHICS_AND_CONSENT.md) for where those
processes actually live. GitHub is the medium this lab uses to keep its
documentation open and versioned; it is not itself a research method.
