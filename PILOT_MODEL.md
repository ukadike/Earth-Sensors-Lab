# Pilot Model

A pilot is how Earth Sensors Lab tests prototypes and curriculum with a real
school, university, museum, library, or community site — as a research
collaboration, not a sales engagement. This document describes what a pilot
involves, phase by phase. No specific pilot described elsewhere in this
repository is complete unless explicitly stated as such.

## What counts as a pilot

A pilot pairs one or more [prototypes](PROTOTYPES.md) or
[curriculum modules](CURRICULUM.md) with a real site, for a bounded period,
with a research question attached (see [RESEARCH_AGENDA.md](RESEARCH_AGENDA.md)).
It is not a purchase of a finished product, and it does not imply a
continuing commercial relationship.

## Phases

### 1. Fit and framing

- Identify which research question(s) the site is positioned to help
  investigate.
- Confirm the site understands the [partnership model](PARTNERSHIP_MODEL.md):
  research collaboration, not fee-for-service vendor relationship.
- Identify funding source (grant, fellowship, sponsor, in-kind) before
  committing the site to costs.

### 2. Consent and ethics review

- Walk through [ETHICS_AND_CONSENT.md](ETHICS_AND_CONSENT.md) with the site's
  decision-makers.
- Prepare consent materials (school, parent/guardian, photo/video as
  applicable) in plain language and in accessible formats.

### 3. Design

- Select the prototype(s) and/or curriculum module(s) appropriate to the
  site type, using the relevant template in [/pilots/](pilots/):
  - [school-pilot-template.md](pilots/school-pilot-template.md)
  - [museum-library-pilot-template.md](pilots/museum-library-pilot-template.md)
  - [community-garden-pilot-template.md](pilots/community-garden-pilot-template.md)
- Confirm accessibility accommodations needed for the specific participants.

### 4. Implementation

- Deploy prototype kit(s) and/or run curriculum module(s) with the site.
- Collect only the data specified in the consent materials, minimized per
  [ETHICS_AND_CONSENT.md](ETHICS_AND_CONSENT.md).

### 5. Evaluation

- Use [/research/pilot-evaluation.md](research/pilot-evaluation.md) to
  structure what was learned — evidence, not conclusions.
- Share findings back with the site partner before or alongside any public
  release, per the community-ownership rule in
  [ETHICS_AND_CONSENT.md](ETHICS_AND_CONSENT.md).
- Record findings using
  [/research/findings-template.md](research/findings-template.md), tagged
  with its evidence status.

### 6. Continuation or close

- Decide with the partner whether the pilot continues, expands, or ends.
- A pilot ending is not a failure state — it is recorded as such in the
  relevant case note.

## Status labels used throughout this repository

- `proposed` — discussed, not yet agreed or funded
- `in development` — agreed, in preparation
- `pilot` — actively running
- `AWAITING FRAGMENT` — referenced but no documentation exists yet in this
  repository
