# Module 2: What Is a Sensor?

Status: in development (draft curriculum, not yet field-tested)

## Learning goals

- Define a sensor as something that converts a physical condition into a
  signal a person or system can understand.
- Compare a human sense (e.g., skin sensing temperature) to an electronic
  sensor (e.g., a thermistor) doing an analogous job.
- Introduce the idea that a sensor's reading always has a translation step
  from raw signal to a number, sound, or image a person can use.

## Materials

- Prototype sensor kit components if available (see
  [/hardware/sensor-kit-overview.md](../hardware/sensor-kit-overview.md)) —
  or printed/described examples if no kit is on hand.
- Student workbook sensor-comparison page.

## Accessibility notes

- The human-sense-to-sensor comparison is chosen specifically because it
  does not require sight: touch (temperature, texture) and hearing (sound
  level) both map directly onto sensor equivalents.
- Any physical sensor components handled in class should have a tactile
  description available, not only a visual one.

## Activity

1. As a class or in small groups, list human senses and one physical
   condition each detects.
2. Introduce one or two sensor types (e.g., temperature, soil moisture) and
   discuss what physical condition each detects and how.
3. Compare: what can the sensor do that a person's senses can't (e.g.,
   precise numeric readings, continuous monitoring)? What can a person's
   senses do that the sensor can't (e.g., context, judgment)?
4. If a prototype kit is available, take one real reading together and
   discuss what it does and doesn't tell you.

## Reflection questions

- What does a sensor "translate," and into what?
- Where might a sensor be wrong or misleading, and how would you know?
- What decision would you still want a person to make, even with good sensor
  data?

## Research notes

Investigates: *How can students learn environmental science through
low-cost sensors?* Establishes the conceptual vocabulary (signal,
translation, reading) used in every later module involving sensors.

## Teacher adaptation notes

- Can be run entirely without hardware, using printed sensor spec sheets or
  described examples, if a kit is not yet available at the site.
- The "do not overclaim" framing from [SSL-METHOD.md](../SSL-METHOD.md)
  applies directly here: encourage students to question what a single
  reading can and can't tell you.
