# Contributing

Earth Sensors Lab welcomes contributions from educators, researchers,
accessibility advisors, hardware/software collaborators, and anyone
interested in accessible STEAM education. This is a research repository, so
contributions are held to the same no-fabrication standard as everything
else here — see [CLAUDE.md](CLAUDE.md).

## Ways to contribute

- **Documentation** — corrections, clarifications, or new module drafts for
  [CURRICULUM.md](CURRICULUM.md), [/accessibility/](accessibility/),
  [/hardware/](hardware/), or [/software/](software/).
- **Accessibility review** — feedback on any accessibility claim or design in
  [ACCESSIBILITY.md](ACCESSIBILITY.md) and [/accessibility/](accessibility/),
  especially from lived experience with assistive technology.
- **Hardware/software prototyping** — see the current prototype status in
  [PROTOTYPES.md](PROTOTYPES.md); most areas are still documentation-only and
  need real implementation.
- **Research** — proposals for study protocols, literature to add to
  [/research/literature-map.md](research/literature-map.md), or evidence from
  a pilot you've run, submitted per
  [/research/findings-template.md](research/findings-template.md).
- **Partnership inquiries** — see [PARTNERSHIP_MODEL.md](PARTNERSHIP_MODEL.md)
  for how to start a conversation about a pilot.

## How to submit

All contribution and feedback happens through GitHub — no email intake:
<https://github.com/ukadike/Earth-Sensors-Lab/issues>

For documentation changes, open a pull request. For larger proposals
(a new curriculum module, a new prototype, a partnership), open an issue
first to discuss fit before writing the full document.

## Ground rules

- No fabricated results, pilots, partners, or studies (see [CLAUDE.md](CLAUDE.md)).
- Use the status vocabulary consistently: `proposed`, `in development`,
  `prototype`, `pilot`, `AWAITING FRAGMENT`, `OPEN QUESTION`.
- New components should include the schema-card fields listed in
  [SCHEMA_CARD.md](SCHEMA_CARD.md) where applicable.
- Accessibility is not optional in any contribution that touches curriculum,
  software, or hardware documentation — see [ACCESSIBILITY.md](ACCESSIBILITY.md).
- Do not redesign the locked visual system (`variables.css`) — see
  [CLAUDE.md](CLAUDE.md).
