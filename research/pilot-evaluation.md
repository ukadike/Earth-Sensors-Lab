# Pilot Evaluation

How a pilot's outcomes are assessed, once one has run. This is a framework,
not a completed evaluation — no pilot has concluded yet.

## What evaluation is for

Evaluation exists to generate honest evidence toward the
[research questions](research-questions.md) a pilot was designed around — not
to produce a success narrative. A pilot that produces ambiguous or negative
evidence is exactly as valuable to record as one that produces clear
evidence.

## Evaluation framework

For each pilot, record:

1. **What was tried** — which prototype(s) and/or curriculum module(s), with
   which site, for how long.
2. **What was observed** — described plainly, distinguishing what was
   directly observed from what is inferred.
3. **What the evidence suggests, and its limits** — sample size, duration,
   confounds, and anything that limits how far the evidence generalizes.
4. **Which research question(s) this bears on**, and what status change (if
   any) is warranted in [research-questions.md](research-questions.md) —
   `OPEN QUESTION` → `EMERGING` requires real, if early, evidence; a single
   small pilot should rarely justify more than `EMERGING`.
5. **Accessibility outcomes** — specific to the accommodations used, per
   [ACCESSIBILITY.md](../ACCESSIBILITY.md).
6. **What the site partner said** — feedback shared back to and reviewed with
   the partner before publication, per the community-ownership rule in
   [ETHICS_AND_CONSENT.md](../ETHICS_AND_CONSENT.md).
7. **What would change next time.**

## Recording findings

Use [findings-template.md](findings-template.md) to write up the result of
applying this framework to a specific pilot. Do not summarize evaluation
results only in prose elsewhere in the repository without a corresponding
findings entry — this keeps evidence traceable to its source.
